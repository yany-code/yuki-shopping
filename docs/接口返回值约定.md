# 接口返回值约定

## 1. 判断顺序

实现一个接口时按以下顺序确定返回值：

1. 先看 `openapi.yaml` 中该路径和 HTTP 方法的 `responses`。
2. 再看接口文档中“说明”和“返回对象”要求：列表、详情、创建结果还是操作确认。
3. 将 `data` 映射为专用 DTO，Controller 返回 `ApiResponse<具体类型>`，不要长期使用 `ApiResponse<?>`。
4. 如果接口只表示“操作成功”，使用 `ApiResponse<Void>`；如果前端下一步需要数据，就返回明确的结果 DTO。

## 2. 按接口语义选择类型

| 接口语义 | Java 返回类型 | data 示例 |
|---|---|---|
| 查询单个资源/当前用户 | `ApiResponse<UserVO>`、`ApiResponse<ProductDetailVO>` | 一个 JSON 对象 |
| 分页查询 | `ApiResponse<PageResult<ProductListVO>>` | `list/page/pageSize/total` |
| 树形查询 | `ApiResponse<List<CategoryTreeVO>>` | 分类节点数组 |
| 普通列表 | `ApiResponse<List<CartItemVO>>` | 数组 |
| 创建资源 | `ApiResponse<CreateOrderResult>` | 新资源编号、状态、金额等 |
| 试算/预览 | `ApiResponse<OrderPreviewVO>` | 明细、金额、运费 |
| 状态变更/删除/确认收货 | `ApiResponse<Void>` | `null` |
| 登录/刷新 Token | `ApiResponse<TokenVO>` | accessToken、refreshToken、过期时间 |
| 支付发起 | `ApiResponse<PayResultVO>` | paymentNo、支付参数、过期时间 |
| 支付回调 | `ApiResponse<Void>` | `null`，由 HTTP 状态和 code 表示已接收 |

## 3. 本项目接口到返回类型的映射

| 路径 | 推荐 Controller 返回类型 |
|---|---|
| `POST /auth/login`、`POST /auth/register`、`POST /auth/refresh` | `ApiResponse<TokenVO>`（注册也可返回 `UserVO`，需和前端约定） |
| `GET /users/me` | `ApiResponse<UserVO>` |
| `PUT /users/me` | `ApiResponse<UserVO>` 或 `ApiResponse<Void>`；推荐返回更新后的用户资料 |
| 地址列表 | `ApiResponse<List<AddressVO>>` |
| 新增/修改地址 | `ApiResponse<AddressVO>`；删除和设默认 | `ApiResponse<Void>` |
| `GET /categories/tree` | `ApiResponse<List<CategoryTreeVO>>` |
| `GET /brands`、`GET /products`、评价列表 | `ApiResponse<PageResult<对应列表VO>>` |
| `GET /products/{id}` | `ApiResponse<ProductDetailVO>` |
| `GET /cart` | `ApiResponse<List<CartItemVO>>` |
| 加购/修改购物车 | `ApiResponse<CartItemVO>` 或返回刷新后的 `CartVO`；删除、全选 | `ApiResponse<Void>` |
| `POST /orders/preview` | `ApiResponse<OrderPreviewVO>` |
| `POST /orders` | `ApiResponse<CreateOrderResult>` |
| 订单分页 | `ApiResponse<PageResult<OrderListVO>>` |
| 订单详情 | `ApiResponse<OrderDetailVO>` |
| 取消订单/确认收货/评价 | `ApiResponse<Void>`；支付发起除外 |
| `POST /orders/{orderNo}/pay` | `ApiResponse<PayResultVO>` |
| `POST /payments/callback` | `ApiResponse<Void>` |
| 管理端分页查询 | `ApiResponse<PageResult<对应列表VO>>` |
| 管理端发货、评价状态修改 | `ApiResponse<Void>` |

## 4. Java 写法

```java
@GetMapping("/{productId}")
public ApiResponse<ProductDetailVO> detail(@PathVariable Long productId) {
    return ApiResponse.ok(productService.detail(productId));
}

@GetMapping
public ApiResponse<PageResult<ProductListVO>> page(ProductQuery query) {
    return ApiResponse.ok(productService.page(query));
}

@PostMapping
public ApiResponse<CreateOrderResult> create(@Valid @RequestBody CreateOrderRequest request) {
    return ApiResponse.ok(orderService.create(currentUserId(), request));
}

@PostMapping("/{orderNo}/cancel")
public ApiResponse<Void> cancel(@PathVariable String orderNo) {
    orderService.cancel(currentUserId(), orderNo);
    return ApiResponse.ok();
}
```

Service 层也使用同样的具体类型：`ProductDetailVO detail(...)`、`PageResult<OrderListVO> page(...)`、`void cancel(...)`。这样编译器会帮助发现“详情接口误返回列表”或“操作接口缺少结果”的问题。

## 5. 返回空值还是返回对象

- 删除、取消、确认收货、设置默认地址、评价提交、发货：只要前端不依赖服务端生成的新数据，返回 `ApiResponse<Void>`。
- 创建订单必须返回 `orderNo`、`status`、`payAmount`，否则前端无法跳转支付或订单详情。
- 登录必须返回 Token；支付必须返回支付流水号或模拟支付参数。
- 更新资料、地址、购物车后，推荐返回更新后的资源，前端可以直接刷新局部状态；如果团队约定统一重新查询，也可返回 `Void`，但要保持所有接口一致。

## 6. 失败响应不随业务类型变化

成功响应的 `data` 使用具体泛型；失败响应始终是：

```java
ApiResponse<Void>
```

由全局异常处理器统一返回 `code`、`message`、`traceId`。例如库存不足返回 `40900`，参数错误返回 `40000`，资源不存在返回 `40400`，请求方法不支持返回 `40500`（HTTP 405）。

## 7. 全局序列化约定（2026-09-08 起生效）

由 `JacksonConfig` 和服务层统一保证，所有 VO 自动遵守，写新接口时不需要单独处理：

- **金额一律字符串**：所有 `BigDecimal` 字段（`price`、`priceMin`、`payAmount`、`avgRating` 等）序列化为字符串并保留标度（`"8999.00"`）；入参同样接受字符串。
- **JSON 列输出结构化对象**：库里的 JSON 字符串列（SKU `specs`、评价 `images`）在 VO 中声明为 `Map<String, String>` / `List<String>`，service 层解析，脏数据兜底为空对象/空数组，禁止把原始 JSON 字符串透传给前端。
- **分页参数不静默改写**：`page`、`pageSize`、价格区间不合规直接抛 `40000`，服务端不做 clamp。

## 8. 当前工程的改造建议

现有 Controller 中的 `ApiResponse<?>` 和 `Map<String, Object>` 适合搭骨架，不适合业务完成后的代码。每实现一个业务接口，应同步建立：`Request DTO`、`Response/VO DTO`、`Service` 方法和 OpenAPI `schema`，然后把 Controller 签名改成明确泛型。最终可以通过 OpenAPI 校验接口实际 JSON 与文档是否一致。
